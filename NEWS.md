# SigRepo_Server 1.0.0
* Documentation: https://montilab.github.io/SigRepo_Server/
* GitHub: https://github.com/montilab/SigRepo_Server/
* The Shiny Home tab now matches the retired React dashboard: a thin title bar with a single "Browse signatures" button, four stat cards with colour-coded icons, and three chart cards (signatures by organism as a donut with a legend, by assay, and the top five contributors) on the same washed-blue background and card styling the React interface used. The Quick Actions card and the footer are gone, as they were in React (#152).
* `docker-compose-local.yml` takes the host address for the Shiny interface from `SHINY_BIND`, default `127.0.0.1`. montilab.bu.edu sets it to `0.0.0.0` so lab members on the BU network open http://montilab.bu.edu:8051 without an SSH tunnel; the database, API and MCP proxy ports stay on loopback, and CONTRIBUTING describes both routes (#142).
* The MCP `run_enrichment` tool is withdrawn until it is rebuilt on the new `SigRepo::runHypeR()` from SigRepo #223, which requires `organism` and `test` and returns hypeR's own objects; the old wrapper failed on every call against the new client. `rummagene_enrich` and the other eight tools are unchanged (#137, rebuild tracked in #138).
* The repository now carries only code, docs and the testthat suite. Removed: a 2024 scratch script and a one-off table builder under `tests/`, a stray `Rplots.pdf`, two unreferenced knitted copies of the client tutorial and an old nav in `legacy_app/www/`, the three type-rename planning documents in `spec/`, and the montilab-specific staging tooling (`scripts/deploy_montilab.sh`, `scripts/reseed_staging.sh`, their shell tests, the fake API fixture and the validate-and-ship skill), which now lives outside the repository. `scripts/smoke_test.sh`, `scripts/smoke_test_ui.R`, the cache builders and the migrations stay (#135).
* The retired React single-page app is removed: `web/` is gone, the `sigrepo-web` service (port 8050) leaves the compose files, CI no longer builds `montilab/sigrepo-web`, and the installer, README and CONTRIBUTING describe the Shiny app alone. The API routes are unchanged (#133).
* `/init_db` and the other admin routes report the failing call alongside the error message instead of a flattened string; the orphaned `mysql/schema/snps_features.sql`, which `generate_db_schema()` never created, is removed. The `/init_db` failure on databases not named `sigrepo` was a client bug, fixed in SigRepo #245 (#130).
